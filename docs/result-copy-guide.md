# 검사 결과 문구 작성 안내

작성 기준: 2026-11-10 현재 SVart 코드. 이 문서는 결과 문구를 쓰는 분과 개발자가 함께 보는 인수인계 자료다. 제안 문장은 검토용 초안이며, 현재 앱 문구와 구분해 표시했다.

**문구를 작성할 때는 [작성용 표](result-copy-worksheet.md)를 복사해서 채워 주면 된다.** 코드나 주파수를 몰라도 작성할 수 있다. 앱은 이번 문서 작성으로 변경하지 않았다.

## 1. 지금 결과는 몇 갈래인가?

| 구분 | 현재 구성 |
| --- | --- |
| 결과 분석 화면의 틀 | 1개. 제목·청감 코드·달팽이·설명 문단이 바뀜 |
| 달팽이 유형 제목 | **9가지**. 고른 저음 3종 × 고른 고음 3종 |
| 첫 번째 설명 문단 | 저음·고음 조합 9가지 |
| 두 번째 설명 문단 | 높은 음을 더 자주 고른 쪽: 왼쪽 / 오른쪽 2가지 |
| 세 번째 설명 문단 | 바탕음 / 함께 / 배음 응답 3가지 |
| 유효한 결과 본문의 조합 | **9 × 2 × 3 = 54가지** |
| 다음 화면 | 분석 뒤 달팽이를 꾹 누르면 작가별 음악 감상 화면으로 이동. 별도의 결과 유형은 아님 |

**9종의 성격 검사나 54종의 청력 진단이라는 뜻은 아니다.** 체험에서 고른 소리를 몇 가지 표현으로 묶어 보여 주는 구조다. 현재 제목과 본문은 8개 검사값을 모두 반영하지 않는다.

미측정·무효 결과는 별도 예외다. 현재 코드는 해당 설명 문단을 생략한다. 마지막 검사가 무효이면 3번째 문단이 없는 조합이 18개 추가되어 72개가 된다. 높은 음 선택 결과까지 없는 상태를 포함하면 문구 조합은 최대 108개다. 예외를 새로운 달팽이 유형으로 이름 붙일 필요는 없다.

## 2. 현재 9가지 제목

현재 제목은 **② 저음 + ③ 고음**만으로 정해진다. ④에서 고른 음역, 음량, 들리는 높은 음의 한계, 중앙 위치는 제목 분류에 쓰지 않는다.

| 저음 선택 ↓ / 고음 선택 → | 부드러운 고음 V | 자연스러운 고음 E | 또렷한 고음 S |
| --- | --- | --- | --- |
| 가벼운 저음 T | 차분한 / quiet — TV | 가벼운 / light — TE | 선명한 / crisp — TS |
| 자연스러운 저음 E | 부드러운 / gentle — EV | 균형 잡힌 / balanced — EE | 또렷한 / bright — ES |
| 풍성한 저음 W | 포근한 / warm — WV | 묵직한 / deep — WE | 풍성한 / vivid — WS |

현재 한국어 제목: `<유형_이름> 달팽이예요`

현재 영어 제목: `Your snail is <type>`

이름을 입력받지 않으므로 관람객 이름 자리나 앞 쉼표를 넣지 않는다. ‘균형 잡힌’이 다른 결과보다 좋은 결과로 읽히지는 않는지도 검토하면 좋다. 영어 quiet는 음량이 작다는 뜻으로 읽힐 수도 있으므로, 저·고음의 느낌을 설명하는 이름으로 적절한지도 검토한다. 제목은 전부 바꿀 수 있지만, 분류 조건을 바꾸는 일과 제목만 바꾸는 일은 구분해서 전달해야 한다.

## 3. 현재 화면에 나오는 문장

### 공통 문장 틀

1. `<저음_느낌>과 <고음_느낌>이 편안한 소리로 느껴졌어요.`
2. `소리로 비유하면 <왼/오른>손잡이예요. 높은 음을 <왼/오른>쪽에서 더 자주 골랐어요.`
3. 아래의 바탕음·배음 문장 중 하나.

| 항목 | 현재 한국어 값 |
| --- | --- |
| 저음 T / E / W | 가벼운 저음 / 자연스러운 저음 / 풍성한 저음 |
| 고음 V / E / S | 부드러운 고음 / 자연스러운 고음 / 또렷한 고음 |
| 바탕음 F | 소리를 받쳐주는 낮은 바탕음을 따라 음의 움직임을 느끼는 편이에요. |
| 함께 B | 낮은 바탕음과 높은 울림을 함께 따라 음의 움직임을 느꼈어요. |
| 배음 H | 소리 위로 겹쳐지는 높은 울림을 따라 음의 움직임을 느끼는 편이에요. |

현재는 선택 횟수·정확한 EQ 조절량을 본문에 넣지 않는다. 청감 코드에는 고른 음역, 저·고음 분류, 가운데 분류, 높은 음 선택 쪽, 바탕음·배음 분류, 높은 음의 한계와 음량 단계가 표시된다.

## 4. 추천 방식: 제목 + 짧은 문장 블록 + 필요한 숫자

**54개의 완성문을 따로 쓰기보다, 같은 역할을 하는 짧은 문장 블록을 조합하는 방식을 추천한다.** 한 문장을 고치면 관련 결과에 함께 적용되므로 한·영 버전을 관리하기도 쉽다. ④의 선호 음역 3가지를 본문에 새로 추가하면 숫자 치환을 제외한 분류 조합도 54×3=162가지로 늘어나지만, 블록 방식에서는 음역 표현 3개만 더 준비하면 된다.

권장 구성은 다음과 같다.

- **제목:** 9가지 이름 중 하나. 달팽이를 소개하는 짧은 말.
- **문장 1:** 이번에 고른 음역과 저음·고음의 느낌. 소리 취향을 가장 먼저 전달.
- **문장 2:** 높은 음을 어느 쪽에서 골랐는지. 숫자를 넣으려면 ‘3번 중 2번’처럼 선택 횟수 사용.
- **문장 3:** 낮은 바탕음과 높은 울림 중 무엇을 따라 응답했는지. 어려운 용어는 풀어 쓰기.

별명을 정하는 것이 어렵다면 **공통 제목 ‘당신이 고른 소리의 모양’ + 선택 결과 문장**도 대안이다. 9개의 이름 대신 고른 소리를 직접 소개하는 방식이며, 취향에 등급이 있다는 인상을 줄이는 데 도움이 될 수 있다. 제목 구조 변경 제안으로 작성용 표 H에 적으면 된다.

⑤의 높은 음 한계나 ⑥의 중앙 위치는 **추가 상세 문장 후보**로 보관해도 된다. 처음부터 8개 검사값을 전부 설명하면 결과가 보고서처럼 길어진다. 추가 항목을 채택한다면 기존 문장과 교체할지, 상세 보기를 만들지 함께 정한다. 상세 보기 기능은 현재 없다.

아이패드는 **가로 화면 전용**이다. 현재 본문은 최대 3문단이며, 가로 화면에서 제목 약 32px·본문 약 20px로 그린다. 초안은 제목 18자 안팎, 본문 문장당 30~45자 안팎·총 3문장을 출발점으로 삼되 실제 화면에서 확인한다. 이는 작성 권장치이지 코드의 글자 수 제한은 아니다. 영어는 별도로 줄바꿈을 확인한다.

### 미술관 관람객에게 맞는 표현

| 설명할 대상 | 권장 표현 예시 | 주의할 표현 |
| --- | --- | --- |
| 음역 선택 | 이번에는 낮게 울리는 멜로디가 가장 편안했어요. | 당신은 100Hz 대역을 좋아합니다. — 필터 중심값을 선호 범위 전체로 단정하지 않기 |
| 저음 조절 | 낮은 울림을 조금 더 풍성하게 골랐어요. | 저음 감도가 낮아서 보정했습니다. |
| 고음 조절 | 높은 소리는 부드러운 쪽이 편안했어요. | 고주파 청력이 약합니다. |
| 높은 음의 좌우 선택 | 3번 중 2번, 더 높은 소리를 오른쪽에서 골랐어요. | 오른쪽 귀가 67% 더 좋습니다. |
| 바탕음·배음 | 소리 밑에 깔린 낮은 울림을 따라 높낮이를 느꼈어요. | 바탕음 정답률 83%, 음악성이 높습니다. |
| 높은 음 한계 | 이번 소리에서는 약 13.2kHz 근처에서 멈췄어요. | 당신의 청력은 13.2kHz입니다. / 청각 나이 |

‘이번 체험에서’, ‘고른’, ‘들렸다고 느낀’ 같은 말이 작품의 성격에 맞다. 좋은 귀·나쁜 귀, 정상·비정상, 정답·오답으로 나누지 않는다. 인구 비교 자료가 없으므로 상위 몇 %, 평균보다 좋음 같은 표현도 쓰지 않는다. ‘소리의 손잡이’ 비유는 현재 문구지만 실제 손잡이나 귀의 능력으로 오해되지 않는지도 검토한다.

## 5. 숫자와 내용을 넣을 자리표시자

아래의 `<...>`는 **문구 작성용 약속**이다. 현재 앱에 이 이름의 치환 기능이 구현된 것은 아니다. 문서가 확정되면 개발자가 실제 저장값을 연결한다. 숫자는 개발자가 계산해 채우므로 작성자가 결과마다 직접 입력하지 않는다.

| 자리표시자 | 예시 | 의미·권장 사용 |
| --- | --- | --- |
| `<유형_이름>` | 또렷한 | 위 9가지 제목 중 선택. 현재 분류 유지 시 사용 |
| `<선호_음역>` | 가운데 높이의 멜로디 | ④에서 고른 낮은 / 가운데 / 높은 음역. 선호한 주파수 범위 전체를 뜻하지 않음 |
| `<저음_느낌>` | 자연스러운 저음 | ②의 3단계 표현 |
| `<고음_느낌>` | 또렷한 고음 | ③의 3단계 표현 |
| `<높은음_선택쪽>` | 오른쪽 | ⑦에서 더 자주 고른 쪽 |
| `<높은음_선택횟수>` | 2 | 그쪽을 고른 횟수. 현재 2 또는 3 |
| `<높은음_전체횟수>` | 3 | 유효한 좌우 선택의 총횟수 |
| `<바탕음_응답수>` | 5 | ⑧에서 바탕음 쪽 움직임에 해당한 응답 수. 정답 수가 아님 |
| `<배음_응답수>` | 1 | ⑧에서 배음 쪽 움직임에 해당한 응답 수 |
| `<음높이_전체횟수>` | 6 | ⑧의 유효 응답 수. 전체 검사 시행 횟수와 구분 |
| `<가청_높이_kHz>` | 13.2 | ⑤에서 멈춘 소리의 높이. 선호한 음역과 다른 값이며, 기기·음량·착용 조건의 영향이 있음 |
| `<가운데_방향>` | 왼쪽 / 가운데 / 오른쪽 | ⑥에서 가운데로 느끼도록 맞춘 가상 소리의 위치. 귀의 건강 상태가 아님 |
| `<편한_크기_단계>` | 6 | 청감 코드의 0~9 기록 단계. 실제 음압 dB나 ‘60% 음량’이 아님 |
| `<청감_코드>` | AES-CRF(13.2k/6) | 체험 기록을 압축한 표시 |

**숫자 사용의 첫 추천은 ‘3번 중 2번’이다.** 주파수·dB보다 바로 이해할 수 있고, 실제 선택을 과장 없이 설명한다. 바탕음·배음 횟수는 용어 설명을 붙여 상세 문장으로 쓸 수 있다. 주파수를 꼭 본문에 넣을 필요는 없다.

### 숫자가 없는 경우

0과 ‘측정하지 못함’은 다르다. 값이 없으면 `0Hz`, `0번`, `undefined`, 빈 괄호로 출력하지 않는다. 해당 문장을 생략하거나 아래처럼 별도 문장을 고른다.

- 현재 동작: 결과가 없는 ⑦·⑧ 문단을 생략.
- 추가 문구 후보: `이번 소리의 움직임은 한쪽으로 묶지 않고 남겨둘게요.`

두 번째 문장은 초안이다. 무효 결과를 ‘복합형’ B로 임의 변환하면 실제 유효한 복합 응답과 섞이므로 조건 변경이 필요하다. 특히 ⑧에서 전부 같은 방향으로 응답하면 끝까지 참여했어도 현재 로직상 결과가 무효일 수 있다.

## 6. 작성 방식 예시

아래는 문장 형식을 보여 주는 **가상 결과**다. 모든 관람객에게 같은 숫자를 보여 주는 문구가 아니다.

| 항목 | 예시 데이터 |
| --- | --- |
| 고른 음역 | 가운데 MID |
| 저음 / 고음 | −3.2dB / +6.4dB → E / S |
| 편한 크기 | 프로필 볼륨 −12dB → 코드 단계 6 |
| 높은 음 한계 / 가운데 | 13,200Hz / +2° → C |
| 높은 음 선택 | 오른쪽 2번, 왼쪽 1번 |
| 바탕음·배음 | 바탕음 응답 5, 배음 응답 1 → F |
| 청감 코드 | AES-CRF(13.2k/6) |

**수정 초안 — 숫자를 적게 쓰는 버전**

> 또렷한 달팽이예요
>
> 가운데 높이의 멜로디에, 자연스러운 저음과 또렷한 고음을 골랐어요.
>
> 3번 중 2번, 더 높은 소리를 오른쪽에서 골랐어요.
>
> 소리 밑에 깔린 낮은 울림을 따라 높낮이를 느꼈어요.

**추가 상세 문장 후보**

> 이번 소리에서는 약 13.2kHz 근처에서 멈췄어요.

추가 문장은 현재 3문장에 자동으로 더하는 것으로 확정한 것이 아니다. 사용한다면 화면 길이와 우선순위를 다시 정한다. ‘주파수’를 설명할 때도 ‘선호한 음역’과 ‘들리지 않게 된 높은 음’을 섞지 않는다.

## 7. 작성·반영 순서

1. [작성용 표](result-copy-worksheet.md)를 복사하고 문서 버전·담당자·날짜를 적는다.
2. 9가지 제목을 유지할지 정하고, 제목 및 본문 블록의 한국어 문구를 작성한다.
3. 숫자를 쓸 항목을 고른다. 예를 들어 ⑦은 선택 횟수 사용, ⑤는 기본 본문에서 제외.
4. 같은 ID의 영어 문구를 작성한다. 영어는 문장 구조·길이가 달라도 되며, 대응하는 값의 의미는 같아야 한다.
5. 개발자는 고정 ID와 자리표시자에 값을 연결한다. 추후 문구를 별도 데이터 파일로 옮기면 작성자는 문구만 교체할 수 있다.
6. 9제목·좌우 2가지·바탕음/함께/배음 3가지·값 없음·긴 영어 문장·아이패드 가로 화면을 미리 보기로 확인한다.

조건이나 숫자의 의미를 바꾸고 싶으면 ‘새 제안’ 열에 적는다. 예: ‘가운데를 3단계 대신 수치로’, ‘9개 제목 대신 공통 제목 1개’. 문구 수정과 검사/분류 규칙 변경을 섞지 않으면 이후 반영이 쉽다.

## 8. 개발자용 연결표

작성자는 이 절을 편집하지 않아도 된다.

| 작성 항목 | 실제 데이터·현재 규칙 |
| --- | --- |
| 저음 / 고음 | `userEQProfile.lowShelf.gain` / `highShelf.gain`, 연속 −10~+10dB |
| 제목 분류 | `shelfToLetter`로 저음 T/E/W, 고음 V/E/S → `getSnailAnalysis`의 9가지 이름 |
| 분류 경계 | 낮춤 `< −4`, 중간 `−4 이상 +4 미만`, 높임 `+4 이상`. 정확히 −4는 중간, +4는 높임 |
| 고른 음역 | `userEQProfile.registerPeak.register`: LOW / MID / HIGH. 앱 A/B/C 자리와 대응 |
| 음역의 EQ 중심값 | LOW 100Hz / MID 400Hz / HIGH 2,500Hz. 선택한 멜로디가 단일 주파수라는 뜻은 아님 |
| 높은 음 선택 쪽 | `psychoProfile.dominantEar`: LEFT / RIGHT |
| 높은 음 선택 횟수 | `psychoProfile.raw.octave.nL` / `nR`; 전체는 `nL+nR` |
| 우세 응답 세기 | `earStrength`: 3:0→100, 2:1→33. 건강 점수·확률·인구 백분위로 사용하지 않음 |
| 음높이 응답 | `psychoProfile.pitchMode`: F / B / H. `raw.f0.F` / `S` / `n`에서 횟수 읽기 |
| 음높이 분류 | 유효 결과에서 `pitchIndex >= 50`이면 F, `<= −50`이면 H, 나머지 B. 6회 모두 유효할 때 F 5~6회 / H 0~1회 / B 2~4회 바탕음 응답 |
| 무효 결과 | `raw.f0.valid` 등 확인. ⑧은 유효 응답 부족이나 한 방향 응답 치우침으로 무효일 수 있음 |
| 높은 음 한계 | `psychoProfile.maxFreqHz`, 현재 8,000~20,000Hz. 표시 예: `(Hz/1000).toFixed(1)` |
| 가운데 | `centerDeg`, `centerImage`: −5° 미만 L / −5~+5° C / +5° 초과 R. 앞뒤를 구별한 값은 아님 |
| 편한 크기 | `userEQProfile.masterVolume`; dB는 `20*log10(volume)`, 코드 단계는 `volumeToDigit` |
| 코드 | `getFullEarCode(userEQProfile, psychoProfile)` |

수치가 연속값인 실제 개인 프로필과 화면의 3단계 분류는 다르다. 코드 글자를 다시 풀어 원래 연속값인 것처럼 설명하지 말고, 본문 숫자는 저장된 실제 값을 읽는다. null 검사는 숫자 변환·반올림보다 먼저 한다.

참고로 청감 코드의 숫자 없는 이산 분류는 `음역3 × 저음3 × 고음3 × 가운데3 × 좌우2 × 음높이3 × 크기10 = 4,860`조합이다. 여기에 높은 음 한계 숫자가 달라진다. **이 4,860을 결과 설명문 4,860개로 작성할 필요는 없다.**
