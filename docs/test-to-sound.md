# 검사 결과가 소리에 반영되는 방식

2026-11-13 기준. 여덟 검사가 각각 감상 음악·달팽이·청감 코드에 어떻게 쓰이는지와, 실제로 걸리는지 잰 결과를 정리했습니다.

## 요약

- **Part 1의 네 검사(① 볼륨, ② 저음, ③ 고음, ④ 음역)는 감상 음악에 실제로 걸립니다.** 필터 값, 필터의 실제 응답, 나오는 소리의 스펙트럼 세 가지로 확인했습니다.
- **Part 2의 네 검사(⑤ 고역 한계, ⑥ 편한 자리, ⑦ 우세 귀, ⑧ 바탕음/배음)는 소리를 바꾸지 않습니다.** 달팽이 모양·색, 청감 코드, 분석 문구, 청감타워 전송에만 쓰입니다.
- Part 2 결과를 소리에 반영할지는 정해지지 않았습니다(원우리 작가 결정 필요).

## 검사별 반영

| 검사 | 재는 것 | 감상 음악에 걸리는 것 | 달팽이 | 청감 코드 |
| :--- | :--- | :--- | :--- | :--- |
| ① 편한 크기 | 전체 음량 −40 ~ 0 dB | **전체 음량**(`masterGain`). 안내 음성·효과음도 −12 ~ +6 dB 범위에서 따라감 | 덩어리 크기 | 끝 숫자 0~9 |
| ② 꼬리(저음) | −10 ~ +10 dB | **200 Hz 아래를 올리거나 내림**(로우 셸프) | 꼬리 길이·말림 | 둘째 글자 T / E / W |
| ③ 머리(고음) | −10 ~ +10 dB | **4 kHz 위를 올리거나 내림**(하이 셸프) | 머리 | 셋째 글자 V / E / S |
| ④ 껍질 자리(음역) | A · B · C 중 하나 | **고른 음역을 +3 dB**(피킹, Q 1). A = 100 Hz, B = 400 Hz, C = 2.5 kHz | 껍질 자리 | 첫 글자 O / A / I |
| ⑤ 고역 한계 | 8 ~ 20 kHz | **없음** | 이중나선 꼬임 | 괄호 안 `13.2k` |
| ⑥ 편한 자리 | 좌우 치우침(도) | **없음** | 선 색 | 넷째 글자 L / C / R |
| ⑦ 우세 귀 | 왼쪽 / 오른쪽 | **없음** | 그쪽 더듬이 움직임 | 다섯째 글자 L / R |
| ⑧ 바탕음·배음 | F / B / H | **없음** | 점액 모양 | 여섯째 글자 F / B / H |

코드 예: `IWS-RLF(13.2k/6)` = 높은 음역(I) · 저음 많이(W) · 고음 또렷(S) − 편한 자리 오른쪽(R) · 왼쪽 귀(L) · 바탕음(F) · 13.2 kHz · 음량 6.

참고로 코드 글자는 실제 값보다 거칩니다. ②③은 ±4 dB를 넘어야 글자가 바뀌지만, 소리에는 고른 값이 그대로(예: +2.5 dB) 걸립니다.

## 소리가 지나는 길

```
감상 음악(여섯 소리) → ② 저음 → ④ 음역 → ③ 고음 → 음량 보정 → ① 볼륨 → 출력
```

- **음량 보정**: EQ를 걸면 전체가 커지거나 작아지므로, 원래 소리와 같은 크기로 들리게 자동으로 되돌립니다(K-가중, ±12 dB 한도). 그래서 '원래 소리 ↔ 내 귀'를 비교할 때 크기가 아니라 음색만 달라집니다.
- **비교 슬라이더**: 왼쪽 끝은 EQ 0, 가운데는 EQ 절반, 오른쪽 끝은 EQ 전부입니다. ① 볼륨은 슬라이더와 상관없이 늘 걸립니다.
- **빈 곳 누르기**: 누르고 있는 동안 EQ 0(원래 소리)입니다.
- **EQ가 걸리지 않는 소리**: ④ 멜로디, Part 2 검사음, 안내 음성, 효과음.
- **휴대폰(청감타워 모바일)**: 같은 세 필터(200 Hz 셸프, 음역 피킹 +3 dB, 4 kHz 셸프)를 씁니다. 코드를 읽어 확인했고 소리는 재지 않았습니다.

## 확인한 결과

`node tests/e2e/eq-apply.mjs <출력폴더>`로 다시 잴 수 있습니다. 검사 결과를 ① −12 dB, ② +8 dB, ③ −6 dB, ④ C(2.5 kHz)로 넣고 감상 화면에서 쟀습니다.

**1. 필터 값** — 모두 넣은 값과 같았습니다.

| 항목 | 넣은 값 | 실제 노드 값 |
| :--- | :--- | :--- |
| ① 볼륨 | −12 dB | −12.0 dB |
| ② 저음 (200 Hz 셸프) | +8 dB | +8 dB |
| ③ 고음 (4 kHz 셸프) | −6 dB | −6 dB |
| ④ 음역 (피킹) | 2.5 kHz, +3 dB, Q 1 | 2.5 kHz, +3 dB, Q 1 |

**2. 필터의 실제 주파수 응답** — 브라우저가 돌려준 응답이 계산식과 0.15 dB 안에서 같았습니다.

| 주파수 | 50 Hz | 100 Hz | 200 Hz | 400 Hz | 1 kHz | 2.5 kHz | 4 kHz | 8 kHz | 16 kHz |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 변화(dB) | +8.0 | +7.5 | +4.0 | +0.6 | +0.5 | +2.2 | −1.5 | −5.5 | −6.0 |

**3. 실제로 나오는 소리** — '내 귀'와 '원래 소리'를 번갈아 8번씩 재서, 저역(40~120 Hz)과 고역(8~14 kHz)의 차이가 얼마나 벌어지는지 봤습니다. 계산상 기대값은 13.7 dB입니다.

| 소리 | 저역 변화 | 고역 변화 | 벌어진 정도 |
| :--- | ---: | ---: | ---: |
| 원우리 자리(임시 녹음) | +5.0 | −11.5 | 16.5 dB |
| 펠릭스 쿠빈 자리(임시 녹음) | +6.5 | −5.8 | 12.3 dB |
| 콜라보 자리(임시 녹음) | +4.7 | −6.7 | 11.4 dB |
| 당현천 | +4.3 | −8.0 | 12.2 dB |
| 중계역 지하철 | +2.4 | −10.4 | 12.8 dB |
| 북서울미술관 앞 | +3.8 | −8.5 | 12.4 dB |

여섯 소리 모두 기대값에 가깝게(±3 dB) 기울었습니다. 녹음이 계속 변하는 소리라 값이 조금씩 흔들립니다. 저역·고역 각각의 숫자가 +8 / −6과 다른 것은 음량 보정이 전체를 함께 움직이기 때문입니다.

**4. 슬라이더와 빈 곳 누르기** — 가운데에서 EQ가 정확히 절반(+4 / +1.5 / −3 dB), 왼쪽 끝과 빈 곳 누르기에서 0이었고 ① 볼륨은 그대로였습니다.

**5. Part 2 결과** — ⑤⑥⑦⑧ 값을 크게 바꿔도 필터·볼륨 값과 응답이 하나도 변하지 않았습니다. 코드에도 이 값을 소리에 쓰는 곳이 없습니다.

## 확인하지 못한 것

- 헤드리스 브라우저에서 잰 숫자입니다. 아이패드와 헤드폰에서 귀로 들은 차이는 확인하지 못했습니다.
- 작가 곡 세 자리는 임시 북서울 녹음으로 쟀습니다. 실제 곡이 오면 다시 재야 합니다.

## 정해야 할 것

Part 2 결과를 소리에도 반영할지 여부입니다. 지금은 "검사한 것이 음악에 입혀진다"는 설명이 Part 1에만 해당합니다. 반영한다면 무엇을 어떻게 걸지(예: ⑤ 한계 위 고역 처리, ⑥⑦ 좌우 균형)는 작가 결정이 필요하고, 코드와 청감타워 모바일 양쪽을 함께 바꿔야 합니다.
