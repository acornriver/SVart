# SVart 오디오 믹스 — 2026-11-10

전체 소리를 더 크게 들을 수 있도록 공통 출력 경로를 만들고, 소스별 불균형과 EQ 비교 시의 음량 변화를 정리했다. 검사의 음높이·박자·순서·좌우 신호와 개인 프로필의 값 범위는 유지한다.

④ 멜로디 → 공통 멜로디 트림 → 관람객 볼륨 → 덕킹 → program 버스

안내 → 안내 슬라이더 → voice 버스

밈 효과음 → 안내 슬라이더 → effects 버스

Part 2 → part2 버스

네 버스 → 공통 +7dB → 스테레오 연동 피크 보호 → 출력 트림·자동 메이크업 보정 → 출력

`audioMix.js`가 모든 최종 출력을 담당한다. 프로그램만 거치던 p5.sound 리미터와 안내·검사의 직접 출력 경로를 통합했다. 앱의 소리가 서로 다른 최종 경로로 나가거나 이중으로 출력되지 않게 한다. FFT는 기존 검사·음악 파형을 계속 읽는다.

## 설정

| 항목 | 설정·의도 |
| --- | --- |
| 공통 출력 상승 | 약 +6dB. 작은 검사 신호의 실제 렌더링 이득으로 확인 |
| 안내 기본 슬라이더 | 0.63 → 0.8. 제곱 게인이므로 기존 기본값보다 약 +4.2dB, 공통 출력 상승을 합치면 약 +10dB |
| 안내 최대값 | 원본 게인 1을 유지하고 공통 출력부 적용 |
| 효과음 | 안내 슬라이더를 공유하고 전용 버스 −1dB. 효과마다 이미 편집된 원본 레벨과 예약 시점을 유지 |
| ④ 멜로디 | 공통 −12dB 트림. 짧은 음의 활성 구간이 비트보다 크게 튀는 현상 조정. LOW/MID/HIGH 기본 보정 +6/0/−2dB와 저장된 현장 보정은 그대로 적용 |
| 비트·녹음 소스 | 내부 K 가중 RMS −26dB 기준 유지. 공통 출력 후 최대 관람객 볼륨에서 약 −20dB 기준 |
| 개인 EQ 음량 보정 | 소스 보정과 동일한 K 가중 필터로 전후 에너지 비교. 기존 A 가중 방식의 극단 EQ 간 레벨 차이를 줄임 |
| ⑥ 중앙 검사 | 정면 HRIR에 실제 비트를 통과시켜 K 가중 레벨 측정 후 공통 게인 하나를 산출. 모든 방향에 같은 게인을 적용해 방향별 좌우 차이를 유지 |
| Part 2 | ① 관람객 볼륨과 분리. 기존 신호 크기·배음·킥·카운트인 비율을 유지하며 공통 출력 상승 적용 |
| 피크 보호 | threshold −5dB, knee 0dB, ratio 20:1, attack 1ms, release 120ms. 출력 trim −1dB 및 자동 메이크업 보정 −2.85dB |
| 덕킹 | 기존 −12dB, 내려갈 때 150ms / 돌아올 때 500ms |

피크 보호는 브라우저의 DynamicsCompressor이며 트루피크 벽돌형 리미터라는 의미는 아니다. 실제 소스·최대 EQ·최대 음성으로 렌더링한 결과를 별도로 검사한다. 큰 소리를 얻기 위해 지속적으로 보호기를 누르는 방식은 피한다.

## 측정·재현

로컬 서버를 켠 뒤:

```sh
node tests/e2e/mix-level.mjs /tmp/svart-mix-audit
python3 scripts/check-mix-truepeak.py /tmp/svart-mix-audit
```

실제 `createRegisterVoice`, `renderBeatLoop`, `octBuffer`, `f0Buffer`, HRIR와 음성·감상 파일을 OfflineAudioContext에서 실제 `AudioMix.createGraph`로 렌더링한다. 결과 JSON과 대표·극단 조건 WAV를 출력한다. 샘플 피크, Part 2의 공통 이득, 비트 EQ 극단값의 레벨 편차를 검사한다.

- 비트 3종, 저·고음 ±10dB × 음역 3종의 극단값
- 감상 녹음 3종의 최대 피크 주변 8초와 극단 EQ
- 멜로디 3종
- 한·영 안내 58개, 기본·최대 레벨
- 크기·껍질·완성 효과음의 중첩, 기본·최대 레벨
- 우세귀 좌/우, 바탕음·배음 6개, 중앙 HRIR 36방향, 고역 8/12/16/20kHz

WAV를 FFmpeg `ebur128=peak=true`로 다시 검사해 LUFS와 트루피크를 측정한다. K 가중 RMS는 채널 평균, LUFS는 표준의 채널 합산·게이팅을 적용하므로 두 숫자를 같은 값으로 취급하지 않는다. 멜로디의 긴 잔향·무음도 활성 구간 LUFS와 전체 RMS가 다른 원인이다.

컨볼버의 `normalize`는 `buffer` 지정 **전에** 설정해야 한다. 실제 앱과 오프라인 측정기에서 순서를 동일하게 맞췄다. [Web Audio 명세](https://webaudio.github.io/web-audio-api/#dom-convolvernode-normalize).

## 실기기 기준

여기의 dB는 디지털 레벨이다. `P2_CAL`과 명목 SPL은 실측 헤드폰 SPL이 아니다. iPad 시스템 음량·헤드폰 연결 상태·착용에 따라 실제 귀에 전달되는 음압이 달라진다. 최종 현장 기준은 동일 iPad와 헤드폰의 시스템 음량을 고정한 상태에서 청취·보정한다. 이번 작업은 브라우저 렌더링 계측이며 실제 헤드폰 청취를 수행한 것으로 간주하지 않는다.
